# 安全架构

## 信任边界

净启包含三个权限层级：

1. 普通应用进程：界面、本地规则、状态、反馈入口和专家治理协调器；
2. Android VPN/无障碍服务：仅在用户通过系统界面授权后运行；
3. Android `adbd` Shell 身份：仅在用户主动开启无线调试并完成系统六位码配对后，通过本机网络连接短暂使用。

任何服务器、规则文件、反馈内容、网页参数和第三方应用界面都不属于可信执行主体。净启不能静默开启开发者选项、无线调试或无障碍，也不会尝试规避 Android 的系统确认界面。

## 内置 ADB 配对

专家模式使用 Android 11+ 标准 ADB TLS/SPAKE2 配对：

1. 用户从净启明确发起配对；
2. 净启启动可取消、五分钟自动超时的前台配对服务并打开开发者选项；
3. 用户预先从系统无障碍页明确开启“净启·开屏守护”，再进入“无线调试”并打开“使用配对码配对设备”的六位码窗口；
4. 用户保持系统窗口在前台。仅当配对状态为 `WAITING_FOR_CODE`、前台包为 `com.android.settings`，且节点树同时具有无线调试配对上下文和唯一六位数字时，开屏守护才会把配对码在同一进程内一次性提交；
5. 净启通过 `_adb-tls-pairing._tcp` 发现端口并执行 TLS/SPAKE2 握手；
6. 配对成功后通过 `_adb-tls-connect._tcp` 发现当前连接端口。

mDNS 发现和 Kadb 套接字在 Android 13+ 明确绑定到当前物理 Wi-Fi，而不是净启 VPN 或移动网络；完成套接字创建后立即恢复原进程网络。解析地址还必须与该 Wi-Fi 的本机地址完全相同。因此，同一 Wi-Fi 中其他设备发布的 ADB 服务不会成为净启的配对或治理目标。

六位配对码只在内存中短暂存在，不写入 Intent extras、偏好设置、文件或日志；提交通过同一进程的一次性字符数组交给前台服务，消费或取消后覆写。读取条件故意收窄，不会把短信验证码、锁屏 PIN、第三方应用或普通设置页面中的六位数字视为配对码。ADB RSA 私钥使用 Android Keystore 内的不可导出 AES-GCM 密钥加密，密文位于 `noBackupFilesDir`。卸载或清除应用数据会删除净启持有的身份材料，用户之后需要重新配对。

Kadb 按名称请求 Bouncy Castle 的 `BC` 提供程序来生成 X.509 身份材料。Android 自带的裁剪版 `BC` 不含该证书工厂，因此仅在首次加载 ADB 身份时，净启会在自己的应用进程中把它替换为 APK 内固定版本的完整 Bouncy Castle 提供程序；这不会修改系统全局提供程序。

## 开屏前台检测

部分澎湃 OS 应用在静态或 Canvas 开屏阶段不发送无障碍窗口事件。开屏守护因此在服务已由用户开启时，每 400 毫秒读取一次当前根窗口的包名：

1. 常驻检查只比较包名，不截图、不记录节点文本，也不持有唤醒锁；
2. 只有真实 `TYPE_WINDOW_STATE_CHANGED` 可以从事件侧切换当前应用，`TYPE_WINDOW_CONTENT_CHANGED` 只能复查已经确认的应用；
3. SystemUI 和当前输入法窗口不能替换当前应用；存在悬浮通知时，只有交互窗口列表中仍存在同包的可见应用窗口，才能通过点击前校验；
4. 包名变化后才启动最长 15 秒的有限节点复查；视觉规则仍使用各自更短的编译时固定窗口和次数；
5. 节点点击和视觉手势派发前都再次验证当前根窗口仍属于同一包和同一次启动代次。

该补偿用于深圳航空一类“根窗口可读、开屏期间不发事件”的应用。窗口包名、节点树和检测结果都只在本机处理。

## 固定命令边界

Kadb 库具有通用 ADB 能力，但净启自己的运行时没有接受任意命令字符串的界面。治理层只能提交以下类型化操作：

- 查询编译时登记的包是否存在；
- 对编译时登记的包执行当前用户移除或恢复；
- 读取编译时登记的系统设置；
- 将固定系统设置写入通过白名单校验的值。

当前唯一包 ID 映射到小米 MSA。当前设置 ID 只映射到浏览器推荐、系统云预下载、预下载任务列表和米享广告。命令文本在 `AdbCommandCatalog` 内由这些 ID 生成；界面、下载规则、反馈、Intent 和网络响应都不能提供包名、设置键或 Shell 片段。未知 ID、带换行/NUL 的值和未登记值会在连接 Shell 之前抛出异常。

## 屏幕数据

携程、爱奇艺和小米音乐等应用可能把跳过按钮绘制在 Canvas/视频层，无法从无障碍节点树读取。净启使用 Android 官方 `AccessibilityService.takeScreenshot`：

1. 只在目标应用同一次启动代次的短窗口触发，并按编译时固定的有限次数复查；
2. Bitmap 只存在于无障碍服务内存；
3. 只计算编译时固定区域的像素特征；
4. 计算后立即关闭硬件缓冲区并回收软件 Bitmap；
5. 第一次命中后立即停止本轮后续节点和视觉点击；
6. 不写磁盘、不跨 Binder、不加入日志、不上传网络。

金融、支付、钱包、证券和保险应用不使用局部视觉匹配。它们只允许经过登记的严格无障碍节点匹配，或完全禁止自动点击。

## 系统治理与恢复

首次治理前同步保存：

- MSA 在当前用户中的安装状态；
- 浏览器推荐设置；
- 系统云预下载设置；
- 预下载任务列表；
- 米享广告设置；
- 快照格式版本和创建时间。

只有快照持久化成功后才允许修改系统。治理和恢复后逐项回读；恢复完成且所有项目验证成功后才删除快照。新版本无法理解旧快照时不得猜测恢复值。

## 远程规则

规划中的规则包采用 Ed25519 离线签名，并包含模式版本、规则修订号、最低客户端版本、生成时间和签名。客户端必须防止版本回滚。

规则包禁止包含：

- Shell 命令；
- Intent URI；
- 文件路径；
- JavaScript；
- DEX、JAR、APK 或原生库；
- 任意系统设置键；
- 任意坐标点击规则；
- 金融应用视觉截图规则。

## 密钥

- APK Release 私钥离线保存，不进入源码或普通 CI 日志；
- 规则签名密钥与 APK 签名密钥分离；
- 授权签名密钥与规则签名密钥分离；
- ADB RSA 私钥由 Android Keystore AES-GCM 密钥加密并排除备份；
- 生产支付密钥和数据库凭证永不进入开源仓库。
